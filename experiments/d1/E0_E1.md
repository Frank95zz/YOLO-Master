## 3. E1 固定安排

| 组 | 输入/模型 | 空间融合 | aux gain | 可训练参数 |
| --- | --- | --- | --- | --- |
| A | 冻结 ViT-S 三层 NPY + Adapter/LatentMixture/Detect | router_only | 0.1 | 3,542,567 |
| B | 同 A | weighted_sum，三个来源等权 | 0.1 | 3,542,567 |
| C | 同 B | weighted_sum，三个来源等权 | 0 | 3,542,567 |
| S | NVMe RGB，从零训练匹配检测器 | 不适用 | 0 | 3,510,624 |

Scratch 可训练参数比冻结下游少约 0.902%，在预注册 1% 匹配范围内；冻结 Teacher 参数不进优化器。
A/B/C 使用完全相同的初始数值 tensor，但分别保留自己的融合方式等非 tensor 元数据。

共同配置：

- 完整 COCO train/val，640 输入，seed0，确定性执行，不做颜色、几何、翻转、mosaic、mixup、copy-paste 或多尺度增强。
- 一组独占六张 A40，顺序 A → B → C → S，不同时跑四组争抢磁盘/GPU。
- 每卡 batch64，全局 batch384，nbs384，每 batch 有效更新一次，不做额外梯度累积。
- 每 rank workers4，特征 prefetch_factor1；训练/验证源均为 NVMe。
- AdamW，lr0=0.001，lrf=0.01，weight_decay=0.0005，warmup3 epochs；保留现有参数分组策略并记录实际组学习率。
- AMP，初始 scale16，growth_interval=1,000,000；溢出只允许受限的同 batch 重放，不能静默跳过参数更新。
- balance=0.01，z=0.001，mixture_aux_budget=3；C 的全局 aux gain=0。
- 保留 **100 epochs 的完整学习率调度，只执行到第 50 轮**。这是 50% 筛选窗口，不是压缩成 50 轮的训练计划。
- 每轮训练内验证、保存 last/best 及 FP32 恢复状态；每 5 轮独立评测标准 COCO AP。
- 标准评测 conf=0.001、max_det=300、完整 5,000 张 val，FP32 权重配合 AMP；两种输入路径使用同一评测协议。
- 完成每组后独立重评 last 和 standard-best。standard-best 是每 5 轮标准 AP 检查点中最佳者，不冒称逐轮标准 AP 最佳。

## 4. 机制、恢复与无效运行

真实训练持续记录 loss、原始 aux、EMA、应用后 aux、AMP scale/重试、有效更新数、数据等待、
单步耗时、显存和 Router 快照。每轮首 batch 记录总损失梯度。

冻结组在第 1/25/50 轮开始前，使用每 rank 两张固定真实样本，在独立 FP32 模型副本上分别求
检测、aux 和总梯度，验证可加性；记录九条 Adapter 分支、Router、residual gain 及融合前后特征幅值。
副本不更新 optimizer，日志 tensor 均脱离计算图，主模型参数/缓冲区和随机状态不受诊断改变。
诊断上下文显式禁用 autocast 与 matmul/cuDNN TF32，正常和异常退出均恢复原设置；
正式训练仍采用原 AMP 配方，原逐元素容限 `rtol=2e-4, atol=2e-5` 不变。

恢复文件包含 FP32 在线模型和 EMA、optimizer、scheduler、AMP scaler、各 rank 的 Python/NumPy/Torch/CUDA RNG、
loader generator、检测损失调度位置、有效更新次数、aux EMA 和实验身份。普通 `last.pt` 与该恢复文件配套使用。
恢复前核对代码、配置、数据、运行 ID 与 epoch；不把标准评测权重当成完整训练状态。

NaN/Inf、aux 隔离、丢 batch、跳更新、错误身份、数据缺失或评测失败会停止编排并保留日志；
不自动改变 batch、模型、学习率或训练预算来“继续”。收到安全停止信号时完成当前 epoch 后保存。
失败后的续跑必须显式指定原运行和 `--resume`；`all` 不默默覆盖已完成的运行。

## 5. 结果选择与计时

主筛选依据是四组第 50 轮的独立标准 COCO AP。Frozen AP 相差不超过 0.005 视为并列，
优先实际训练作业耗时更低者，仍并列保留 A。窗口内 best 只作补充。
最佳 Frozen 相对 Scratch 的 AP 保留率低于 80% 时暂停完整 COCO 多 seed 矩阵，不自动进入 E2/E4。

四组分别执行一次完整 epoch 基准，覆盖全量加载、训练、每轮验证和保存。
基准独立输出，不计入正式筛选结果。保留原始单 epoch 作业耗时，并从逐轮记录中分离启动开销：
总时长估计为 `sum(50 * epoch_wall + (job_wall - epoch_wall)) + 48 * 90` 秒，
避免把数据索引初始化开销重复计入 50 次。原始保守估计与校正后估计均保留在证据中。
额外为四组各 12 次标准/最终评测预留每次 90 秒；实际评测时间仍单独记录。
E1 启动后的检查间隔为该实测总预计时间的 1/4，向上取整到分钟，不高频轮询。

筛选作业 wall time 与独立最终评测分别保留；wall time 包含训练中固定周期评测的等待。
GPU-hours 按实际占用的六卡时长统计，不把单卡墙钟时间直接当 GPU-hours。
后续 P1 冷启动与缓存摊销计算必须另外加入特征抽取/准备成本，本阶段不提前宣称成本下降。

## 6. 复现入口

本批 E1 已完成，以下启动/恢复命令和验收记录保留作复现及历史说明，不应再次用于启动已完成任务。

以下命令在已安装仓库依赖、可用六张 CUDA 卡的 Linux 环境中执行。`WORK` 必须为仓库外的新目录。
路径通过参数注入；所有大文件、进度、完整日志、预测、checkpoint 和恢复文件均不进入 Git。

安全暂停当前编排：

```bash

```
