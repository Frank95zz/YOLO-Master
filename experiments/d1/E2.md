## 3. 官方评测协议

官方工具：[VisDrone2018-DET-toolkit](https://github.com/VisDrone/VisDrone2018-DET-toolkit/tree/005445782213e20cb91bc50a597db3dd949e749a)，
固定 commit `005445782213e20cb91bc50a597db3dd949e749a`；每个文件的 SHA256 见
[工具 manifest](manifests/visdrone-toolkit.json)。

导出原图 xywh、类别 1..10 的逐图 TXT。conf=0.001，按分数稳定降序后每图最多 500 个预测。
空预测写空 TXT，导出器不追加 NMS；模型端的端到端解码或 NMS 需另行登记，不混用后处理。
官方 `dropObjectsInIgr`、`evalRes`、`calcAccuracy`、`VOCap` 原样调用；保留其 ignore、匹配、截断及汇总行为。
AP 使用 IoU 0.50:0.05:0.95，AR 使用 maxDets 1/10/100/500。百分制原值保留，同时除以 100 输出统一比例值。
这是锁定工具的结果，不是普通 COCO AP，不与 COCO 数值混为一套指标。

封装仅增加文件与哈希检查、JSON 输出及空 TXT 的 `zeros(0,8)` 输入处理。
本机 MATLAB R2026a Update 5 可用，但缺少 Image Processing Toolbox 的 `mean2`；
提供 `mean(value(:))` 的明确兼容实现，仅在原函数不存在时启用，不修改官方匹配/AP 源文件。

验收：固定排序前 8 张真实 val 图片，使用 GT 派生的确定性预测，
与官方 `saveAnnoRes -> calcAccuracy` 的七项指标逐项比较，最大绝对差 **0**（门槛 1e-6）。
另通过精确 IoU 边界、重复检测、score=0 匹配、ignore 区域及十类空预测测试。
**这些是评测工具的测试夹具，不是训练模型的检测成绩。** 本阶段不引入 Python AP 替代实现。
实际测试摘要见 [MATLAB 验收](manifests/e2-visdrone-matlab-tests.json)。

## 4. 缓存协议与恢复

- DINOv3 ViT-S/16，block4/8/12，640 LetterBox 与既有 WP0 归一化；每图三组 FP16 `[384,40,40]`。
- train+val 共 7,019 图、21,057 个 tensor，原始特征约 24.10 GiB；保留 safetensors 和 NPY 时约 48.2 GiB 加元数据。
- 六进程各使用一张 GPU，batch16；排序后 `index % 6 == rank` 分区，每个 rank 的首尾批次被记录。
- 续跑不重新压紧剩余样本的 batch：部分批次缺失时重算完整原批次，只补未提交样本，保持 FP16 上下文。
- 每个 rank 有独立目录/锁/日志/收据。正式索引只在全部 rank 身份、数量、哈希通过后发布。
- 原始重复图片保留独立样本 ID；同一 rank 重复内容在分片边界隔离，避免共享 tensor key 覆盖不同批次结果。
- 对每个 rank 的首批与尾批按原上下文在线抽查，报告每层最大/平均绝对误差，门槛 rtol=atol=1e-3。
- 每图 NPY 形状为 `[3,384,40,40]`，转换前后逐层 SHA256 相同，独立读回验证；**不删除 safetensors 源件**。
- `.part` 残留、缺失 rank、错误身份和损坏文件拒绝发布；不得为恢复而删除已经校验通过的正式文件。
- 原有 `/root` 限定且删除源分片的迁移命令不变；新入口仅负责 VisDrone train/val 的非破坏转换。
- NPY 读取器增加独立 `visdrone-train/visdrone-val` 命名空间，不放宽 COCO 12 位 ID 检查。
- 数据、权重、缓存位于同一显式指定的本地文件系统，拒绝 NFS/CIFS；200 GiB 可用空间是启动门槛。

## 5. 复现入口

从仓库根目录运行，先激活已有 D1 环境。以下路径均由使用者注入：

```bash
export NVME_ROOT=/path/to/local-nvme/d1-tmp
export E2_WORK=/path/to/external/e2-work
export D1_WEIGHTS="$NVME_ROOT/weights/dinov3-vits16-pretrain-lvd1689m"

python -m scripts.d1.prepare_visdrone \
  --source "$NVME_ROOT/datasets/VisDrone" \
  --output "$NVME_ROOT/datasets/visdrone-d1-v1"
python -m scripts.d1.prepare_visdrone \
  --source "$NVME_ROOT/datasets/VisDrone" \
  --output "$NVME_ROOT/datasets/visdrone-d1-v1" --verify-only

# 在干净提交上执行；预计超过 3 分钟应由 nohup/作业系统托管。
python -m scripts.d1.cache_visdrone all --repo "$PWD" \
  --data "$NVME_ROOT/datasets/visdrone-d1-v1" --weights "$D1_WEIGHTS" \
  --output "$NVME_ROOT/visdrone-d1-e2-v1" --devices 0,1,2,3,4,5 --batch 16

python -m scripts.d1.evaluate_visdrone fixture \
  --source "$NVME_ROOT/datasets/VisDrone/VisDrone2019-DET-val" \
  --output "$E2_WORK/evaluator-fixture"
```

正式预测导出入口（JSON 为字符串 `image_id`、0..9 `category_id`、原图 `bbox=[x,y,w,h]` 和 score）：

```bash
python -m scripts.d1.evaluate_visdrone export \
  --predictions "$E2_WORK/predictions.json" \
  --image-list "$NVME_ROOT/datasets/visdrone-d1-v1/val.txt" \
  --output "$E2_WORK/predictions-txt"
```

在有许可的 MATLAB 上添加 `scripts/d1` 到路径后调用：

```matlab
report = evaluate_visdrone_official(toolkitDir, originalSplitDir, predictionDir, outputJson, toolkitManifest);
test_visdrone_official(toolkitDir, fixtureDatasetDir, fixturePredictionDir, testOutputDir, toolkitManifest);
```

所有参数显式提供；`toolkitManifest` 指向仓库 `experiments/d1/manifests/visdrone-toolkit.json`。
大缓存、官方工具副本、真实图集与完整日志不进入 Git。
