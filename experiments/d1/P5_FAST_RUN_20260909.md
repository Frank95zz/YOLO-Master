# P5 三架构提速版本正式筛选登记

登记日期：2026-09-09。用户已批准按实验计划第 6.5 节开展 BASE、DW、BN64 三组对照，并要求启动前回收冗余内存、确认无 FinsSim 仿真进程。

本文固定本轮执行合同，不改写 [P1/P2 总体计划](P1_P2_EXPERIMENT_PLAN.md) 中用户正在编辑的内容，不复用旧暂停训练的中间权重。实际启动时间、代码 commit、PID、配置和初始张量 SHA256 以外部工作区的 `matrix.json`、`suite-launch.json` 和 `launch-receipt.json` 为准；本登记不预写实验结果。

## 1. 三组结构与配对

共同路径：冻结 DINOv3 ViT-S/16 的 block4/8/12 FP16 缓存，九条 Adapter 分支，三个 LatentMixture，YOLO26 Detect。三组只改变 P5，其他网络、初始化规则和训练设置一致。

| 组别 | 每个来源的 P5 分支 | P5 参数 | COCO 下游可训练参数 |
| --- | --- | ---: | ---: |
| BASE | 普通 3x3，384 到 256，stride2 | 2,655,744 | 3,542,567 |
| DW | 深度卷积 3x3，384 到 384，stride2；再 1x1，384 到 256 | 309,120 | 1,195,943 |
| BN64 | 1x1，384 到 64；再普通 3x3，64 到 256，stride2 | 518,016 | 1,404,839 |

每个卷积后接 GroupNorm 与 SiLU。BN64 指 64 通道瓶颈，不是 BatchNorm。参数统计不含冻结 Teacher。
非 P5 张量复用 E1 的配对初始状态；BASE 还复用原始 P5，另外两组的 P5 以 seed0 初始化。三组分别严格加载各自配置，不从旧 best/last 继续微调。

## 2. 固定实现

- P3：`p3_upsample_mode=separable_bilinear2x`，保留确定性和双线性 2 倍上采样定义，不使用 torch.compile。
- EMA：`ema_implementation=foreach-v1`，已完成同执行路径下的新旧实现逐位一致验收。
- 恢复：`resume_temperature_policy=epoch-boundary-v1`、`resume_rank_buffers=true`。
- 融合：`weighted_sum`，三个来源权重固定归一化为 1/3；每尺度四个专家，密集执行。
- 不加入可学习来源权重、P3 新卷积、跨尺度 Neck、更大 Teacher、GPU 预取或 Router 统计合并。

参见 [P3 提速证据](P3_UPSAMPLE_RESULTS.md)、[EMA 接入验收](EMA_BATCHING_RESULTS.md)、[恢复诊断](RESUME_DIAGNOSTICS.md)。P3 替换的反向舍入与旧实现不保证逐位一致；DDP 跨进程恢复也仍有归约舍入差异。因此本轮三组全部从配对初始化重新开始，不能把旧实验的精度或成本直接当成本轮 BASE。

## 3. 训练与评测合同

| 项目 | 固定值 |
| --- | --- |
| 数据 | COCO 2017，train2017=118287，val2017=5000，80 类 |
| 输入 | 640x640，原 LetterBox/RGB/归一化合同，关闭全部原已禁用的数据增强及多尺度训练 |
| 存储 | 已校验的本机 NVMe RGB、标签、官方标注和 NPY 特征；不回退到 NFS |
| 顺序 | BASE -> DW -> BN64，串行使用同一组六张 A40 |
| 预算 | 每组 seed0，100 epoch 余弦调度的前 50 epoch，15450 次有效更新 |
| batch | 每卡64，全局384，nbs384，每 batch 一次更新，不额外梯度累积 |
| 数据加载 | workers4/rank，prefetch1，保留尾批与 DDP 补齐规则 |
| 优化器 | AdamW，lr0=0.001，lrf=0.01，weight_decay=0.0005，momentum/beta1=0.9 |
| warmup | 3 epoch，沿用既有 warmup bias LR 和分组学习率规则 |
| 数值 | deterministic=True，AMP，初始scale16，growth_interval=1000000 |
| 检测损失 | box7.5、cls0.5、dfl1.5；end2end=True、reg_max=1 |
| aux | balance0.01、z0.001、latent_aux_gain0.1、mixture_aux_budget3.0；scalar-once-v1 |
| 监控 | 每 epoch 内置验证；每5轮保留 checkpoint 并独立标准 AP 评测 |
| 最终结果 | 固定第50轮为主；last 和 standard-best 均独立严格重载、评测 |
| 失败处理 | 停止当前队列，不自动换配方、跳组或延长预算；明确确认后才恢复 |

已验证代码按相同规则分组学习率，不把基础 lr0 当作所有参数组始终相同的实际 LR。实际组值、warmup 和调度状态由各组 `args.yaml`、日志与恢复状态记录。

固定筛选线：相对本轮 BASE，第50轮标准 AP 下降不超过0.5点，AP75/AP_large 各下降不超过1.0点，同时实际训练加最终评测 GPU-hours 更低。AP_small 单列。单 seed 只用于候选筛选，不宣称统计等效或 P1 的50%成本目标已经达成。

## 4. 运行隔离和资源门禁

1. 只提交本轮已验证的 D1 代码、测试及相关报告，保留主工作区中用户的未提交计划修改原样；不将其强行纳入提交。
2. 从固定 commit 建立独立、干净的 detached worktree。准备、训练和评测均从该目录运行，避免主工作区后续编辑改变长任务代码。
3. 使用新的外部实验目录，拒绝已有 matrix/启动状态或实验产物的覆盖。不修改旧 E1、旧 DW、旧提速准备工作区。
4. 记录容器内存上限与占用，不能用宿主机 MemAvailable 冒充容器可用内存。启动前观测的 cgroup 上限为176 GiB；运行时重新读取。
5. 检查进程命令、工作目录与进程树；FinsSim 的空闲终端/编辑器不等同仿真任务，不为释放内存关闭它们。若出现活动仿真或其他训练任务，先停止启动操作并报告。
6. 仅对指定 D1 文件调用 Linux 文件缓存回收建议，不删除数据或权重、不分配大数组施压、不写宿主机全局 drop_caches、不终止无关进程。回收前后数据记入 `prelaunch-cleanup.json`。
7. 已存在低显存 GPU 保活程序，目标利用率10%，按代码在外部负载升高后让路。保留它，启动后核对其让路状态，不把它当作 FinsSim；如未让路造成竞争，应先处理并记录，不隐去干扰。
8. 队列通过独立会话后台运行，日志/PID/状态保存在外部工作区；结束后再回收本轮特征文件缓存。首次启动核验六 rank 更新、有限 loss、AMP 状态与实际模型配置，不持续等待三组训练完成。

## 5. 时间和产物

依据此前六卡真实 batch 短基准，P3 优化后三组约335-340 ms/step，按309步/轮外推纯训练约103-105秒/轮。EMA 的生产实现没有新的完整 COCO 耗时证明，不把微基准收益叠加为保证。

启动前预算仍按每组约1.7-2小时、三组合计约5-6小时估计，包含常规验证、周期标准评测、最终评测与初始化的预留。资源和实际完整 epoch 会改变 ETA；这不是测得的最终 GPU-hours，也不是新的50%降本结论。

每组保存 `runs/P5-*/results.csv`、权重、`reports/P5-*/` 分 rank 进度/机制/时间/显存、标准评测、恢复状态及成本。整个队列记录 `status.json`、`jobs/`、日志和最终 `suite-summary.json`。启动前回收和队列结束后回收在训练计时之外，各自有独立报告。

本次仅启动第6.5节三架构筛选，不启动 Scratch、VisDrone aux 网格、更大 Teacher 或其他正式实验。GitHub 推送不属于本次启动操作。
