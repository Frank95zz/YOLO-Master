## 1. 三组结构与配对

共同路径：冻结 DINOv3 ViT-S/16 的 block4/8/12 FP16 缓存，九条 Adapter 分支，三个 LatentMixture，YOLO26 Detect。三组只改变 P5，其他网络、初始化规则和训练设置一致。

| 组别 | 每个来源的 P5 分支 | P5 参数 | COCO 下游可训练参数 |
| --- | --- | ---: | ---: |
| BASE | 普通 3x3，384 到 256，stride2 | 2,655,744 | 3,542,567 |
| DW | 深度卷积 3x3，384 到 384，stride2；再 1x1，384 到 256 | 309,120 | 1,195,943 |
| BN64 | 1x1，384 到 64；再普通 3x3，64 到 256，stride2 | 518,016 | 1,404,839 |

每个卷积后接 GroupNorm 与 SiLU。BN64 指 64 通道瓶颈，不是 BatchNorm。参数统计不含冻结 Teacher。
非 P5 张量复用 E1 的配对初始状态；BASE 还复用原始 P5，另外两组的 P5 以 seed0 初始化。三组分别严格加载各自配置，不从旧 best/last 继续微调。

## 2. 固定实现

- P3：`p3_upsample_mode=separable_bilinear2x`，保留确定性和双线性 2 倍上采样定义，不使用 torch.compile。
- EMA：`ema_implementation=foreach-v1`，已完成同执行路径下的新旧实现逐位一致验收。
- 恢复：`resume_temperature_policy=epoch-boundary-v1`、`resume_rank_buffers=true`。
- 融合：`weighted_sum`，三个来源权重固定归一化为 1/3；每尺度四个专家，密集执行。
- 不加入可学习来源权重、P3 新卷积、跨尺度 Neck、更大 Teacher、GPU 预取或 Router 统计合并。

参见 [P3 提速证据](P3_UPSAMPLE_RESULTS.md)、[EMA 接入验收](EMA_BATCHING_RESULTS.md)、[恢复诊断](RESUME_DIAGNOSTICS.md)。P3 替换的反向舍入与旧实现不保证逐位一致；DDP 跨进程恢复也仍有归约舍入差异。因此本轮三组全部从配对初始化重新开始，不能把旧实验的精度或成本直接当成本轮 BASE。

## 4. 运行隔离和资源门禁

1. 只提交本轮已验证的 D1 代码、测试及相关报告，保留主工作区中用户的未提交计划修改原样；不将其强行纳入提交。
2. 从固定 commit 建立独立、干净的 detached worktree。准备、训练和评测均从该目录运行，避免主工作区后续编辑改变长任务代码。
3. 使用新的外部实验目录，拒绝已有 matrix/启动状态或实验产物的覆盖。不修改旧 E1、旧 DW、旧提速准备工作区。
4. 记录容器内存上限与占用，不能用宿主机 MemAvailable 冒充容器可用内存。启动前观测的 cgroup 上限为176 GiB；运行时重新读取。
5. 检查进程命令、工作目录与进程树；FinsSim 的空闲终端/编辑器不等同仿真任务，不为释放内存关闭它们。若出现活动仿真或其他训练任务，先停止启动操作并报告。
6. 仅对指定 D1 文件调用 Linux 文件缓存回收建议，不删除数据或权重、不分配大数组施压、不写宿主机全局 drop_caches、不终止无关进程。回收前后数据记入 `prelaunch-cleanup.json`。
7. 已存在低显存 GPU 保活程序，目标利用率10%，按代码在外部负载升高后让路。保留它，启动后核对其让路状态，不把它当作 FinsSim；如未让路造成竞争，应先处理并记录，不隐去干扰。
8. 队列通过独立会话后台运行，日志/PID/状态保存在外部工作区；结束后再回收本轮特征文件缓存。首次启动核验六 rank 更新、有限 loss、AMP 状态与实际模型配置，不持续等待三组训练完成。

### 6.2 成本与数据等待

| 组别 | 训练作业墙钟 / s | 平均每 rank 每轮 step_seconds / s | 平均每 rank 每轮数据等待 / s | 活动作业 GPUh | 六卡保留 GPUh |
| --- | ---: | ---: | ---: | ---: | ---: |
| BASE | 6149.327 | 105.425 | 0.200 | 10.278431 | 10.426199 |
| DW | 6199.929 | 106.235 | 0.199 | 10.363558 | 10.515275 |
| BN64 | 6236.637 | 106.944 | 0.211 | 10.424189 | 10.573163 |

- 训练作业墙钟包含初始化、训练、常规验证和周期标准评测；两次最终独立评测另计。
- 活动作业 GPUh = `(6 * train_seconds + final_last_job_seconds + final_best_job_seconds) / 3600`。
  最终评测各用一张 GPU。该指标按作业占用时长记账，不是 GPU 利用率积分，也不是纯 CUDA kernel 时间。
- 六卡保留 GPUh = `6 * (train_seconds + final_last_job_seconds + final_best_job_seconds) / 3600`，
  用于表示最终评测时仍保留整组六卡的机会成本。
- step_seconds 和 data_wait_seconds 来自各 rank 的逐 epoch 计时，先在 50 轮内平均，再对六 rank 平均。
  数据等待只是显式取 batch 的阻塞，不等于全部 CPU、I/O 或 DDP 等待；不能跨 rank 相加成墙钟。
- 三组活动作业合计 31.066179 GPUh。队列从 16:55:53.791 到 22:11:03.216，
  约 5 小时 15 分 9 秒；日志时区为北京时间。

按原筛选规则，DW 和 BN64 的 `retained=false`：精度容差通过，但实际 GPUh 均未低于 BASE。
不因 BN64 精度更高而事后改写“同时更省时”的门槛，也不把参数减少解释为 P1 的 50% 降本。
BN64 仍可作为后续精度候选，但不是已通过成本门槛的替代方案；原 P5 继续保留，最终架构须另行确认。

### 7.1 排除已知 FinsSim 重叠轮次后的训练时间

2026-09-10 补充：以下对已有日志做事后描述统计，没有重新训练。
“正常轮次”在这里仅指未与已记录 FinsSim 窗口重叠，不代表已证明完全没有其他争用或余波。

将外部任务窗口前后各扩大 1 秒后，剔除集合不变。原始文件写入时刻与计时起点重建仍存在小幅边界误差。
没有按耗时、loss 或精度挑选快轮次；另列去掉 warmup 第 1-3 轮的 39 轮敏感性统计。
