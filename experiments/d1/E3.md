# E3: BN64 / VisDrone 辅助损失扫描

## 1. 决策与范围

2026-09-10 用户确认以 BN64 作为后续冻结模型基座；随后将 E3 缩减为 seed 0、1、2，以控制总耗时。
本次修改发生在任何 E3 正式训练开始之前，不是根据训练结果删除种子。
完整研究方案见 [P1/P2 实验计划第 8 节](P1_P2_EXPERIMENT_PLAN.md#8-e3-p2-辅助损失扫描仅-visdrone全部候选三-seed)。

只在 VisDrone 开展 aux 扫描，不重跑 COCO、不启动 E4、不重建 Teacher 缓存。
BN64 的 COCO 筛选精度和参数量支持采用它，但不证明其 GPU-hours 低于 BASE，亦不代表 P1 的 50% 成本目标达成。
历史结果与成本判据保留于 [P5 报告](P5_FAST_RUN_20260909.md)。

## 2. 固定架构与训练

| 项目 | 设置 |
| --- | --- |
| Teacher | 冻结 DINOv3 ViT-S/16，block4/8/12，三组 FP16 384x40x40 缓存 |
| Adapter | 九条独立分支；P5 为 384->64 的 1x1 卷积，再接 64->256 的 3x3 stride2 卷积；均带 GN+SiLU |
| P3 提速 | `separable_bilinear2x`，不改变已确认的插值语义 |
| 融合/检测 | weighted_sum [1,1,1] 归一化，三个 LatentMixture 各 4 个 dense 专家；YOLO26 end-to-end 10 类头 |
| 下游参数 | 1,340,259；不含冻结 Teacher，Teacher 不进入 optimizer/checkpoint |
| 数据 | 官方 train 6,471 张 / val 548 张；test-dev 不参与筛选；RGB 与缓存都使用已验证的本地 NVMe 副本 |
| 预算 | 完整 300 轮学习率调度，只训练前 60 轮；seed0/1/2 |
| 硬件与 batch | 6 张 A40，16/card，全局96，nbs96，每 batch 更新一次 |
| 数据加载 | 每 rank 4 workers，prefetch1，无在线 Teacher，无增强 |
| 优化器 | AdamW，lr0=0.001，lrf=0.01，momentum=0.9，weight_decay=0.0005，cos_lr，warmup3 |
| AMP/EMA | AMP FP16，初始 scale16，growth_interval1000000；模型 EMA foreach-v1 |
| 恢复 | optimizer、scheduler、scaler、criterion、RNG、loader generator、aux EMA、rank-local buffers；epoch-boundary-v1 温度策略 |
| 损失 | scalar-once-v1；只变化预注册的 balance/z/gain，mixture_aux_budget=3.0 |

每个 seed 独立初始化。相同 seed 的所有候选读取同一个初始 tensor 文件，校验 SHA256；非 tensor 配置按候选分别绑定。
不加载 COCO 训练后的下游权重。相同 seed 使用相同采样和 batch 规则。

## 3. 两阶段矩阵

| 阶段 | 候选 | seeds | 新训练数 |
| --- | --- | --- | ---: |
| 第一阶段 | balance={0,0.01,0.1} x z={0,0.001,0.01}；gain固定0.1 | 0/1/2 | 27 |
| 第二阶段 | 固定首阶段最佳非全零系数组合；gain={0,0.03,0.1,0.3} | 0/1/2 | 9，复用首阶段gain0.1的3次结果 |

合计36次、2,160个训练epoch，较原四种子48次减少25%。顺序先默认、全零，再其余七个组合，每组跑齐三个种子。
不因 seed0 结果差而淘汰其他种子，不依据内部 mAP 选参，不丢弃失败或中断记录。

第一阶段完整27次官方第60轮 AP 齐备后，以三种子原始0..1 AP的均值选择最佳非全零 balance/z。
全零组可以整体领先，仍如实报告；第二阶段保留 gain0 对照。
均值完全相同时依次比较样本标准差、可比的平均GPUh、参数元组升序；不使用E1的0.5AP容差。
统计 n=3，样本标准差分母2；探索性95% t区间自由度2，系数约4.303，不冒充独立显著性确认。
首阶段汇报后，第二阶段9次另行确认；当前入口不会自动启动第二阶段或E4。

## 5. 指标与官方评分

每轮保存内部loss/精度、各rank step/wait、峰值显存、有效optimizer更新、AMP重试及路由快照。
每轮开始在每rank固定两张训练图、独立FP32模型副本上测量真实候选的raw balance/z、加权项、aux EMA分母、预算缩放、effective_aux、aux/native比例和分离梯度范数。
探针恢复RNG、不修改源模型或aux EMA，不改变训练图；它是固定样本诊断，不是全数据集每轮均值。
全零系数时核心模块会短路raw aux计算；额外记录的detached路由统计避免把返回0解释成真实负载完美均衡。

每5轮严格重载并导出548张val预测，保存对应checkpoint及SHA256；GPU导出时间计入当前训练作业GPUh。
继续使用 E2 锁定的官方 MATLAB 工具和 ignore 语义，不移植未经对齐的新评测器。
固定工具commit为 `005445782213e20cb91bc50a597db3dd949e749a`，工具清单见 [manifest](manifests/visdrone-toolkit.json)。
本机 MATLAB 评分可在训练后批处理；这是评分调度的变化，不改变预测、官方匹配或固定epoch选择规则。
未取得评分时状态为 `AWAITING_OFFICIAL_MATLAB`；不得用内部mAP代填官方AP，不提前生成standard-best或AUX_STAR。
全部每5轮评分补齐后按官方AP选择standard-best；主结果始终是第60轮。MATLAB与传输耗时另列，不虚构GPU成本，也不忽略端到端墙钟。

沿用 [E2说明](E2.md) 的10类转换、ignore保留、无训练ignore-region mask和数据重复ID边界，不将这些限制隐藏。

## 6. 复现与状态

在干净的本分支代码提交上，从仓库根目录运行。以下变量由运行环境传入，不在Git合同中硬编码服务器路径。

```bash
python -m scripts.d1.run_e3 prepare --workspace "$E3_WORKSPACE" --data "$VISDRONE_DATA" --cache "$VISDRONE_NPY"
python -m scripts.d1.run_e3 suite --workspace "$E3_WORKSPACE" --approved --gates-only
# 验收通过后，使用同一工作区和代码版本启动第一阶段。
nohup python -u -m scripts.d1.run_e3 suite --workspace "$E3_WORKSPACE" --approved > "$E3_WORKSPACE/suite.log" 2>&1 < /dev/null &
echo $! > "$E3_WORKSPACE/suite.pid"
python -m scripts.d1.run_e3 status --workspace "$E3_WORKSPACE"
```

首阶段训练全部完成后队列停在 `STAGE1_TRAINED_AWAITING_OFFICIAL_MATLAB`。
把固定官方工具生成的评分放到各 `reports/<run-id>/official/epoch-NNN/official-matlab.json` 后再汇总：

```bash
python -m scripts.d1.run_e3 summarize --workspace "$E3_WORKSPACE"
```

评分报告必须对应当前导出SHA256和548张图片；汇总会校验官方工具、checkpoint、预测文件与候选身份。
仅执行到首阶段汇总，第二阶段具体启动安排等待其结果。
